# 首个发布版本 MVP

**状态：**已确认的规格；实现与验收证据尚未完成。

**决策基线：**2026 年 11 月 13 日。

**权威版本：**[英文文档](MVP.md)为主版本。本中文镜像必须保留相同需求编号、范围与验收条件。含义变化时，必须在同一个 PR 中同步更新。

协作要求见 [CONTRIBUTING.md](../CONTRIBUTING.md)，安全与私密数据处理见 [SECURITY.md](../SECURITY.md)。研究结论为规格提供参考，不能覆盖已确认范围。

## 1. 产品目标与用户

交付一款 iPhone 应用，帮助新西兰初级至中级徒步者完成半日或一日徒步的准备、路线跟随与记录。首版必须可靠完成一个有用的完整流程：

**选择或导入路线 → 查看信息 → 准备离线地图 → 开始徒步 → 查看位置与偏离提醒 → 结束 → 查看并导出轨迹。**

从团队方便实测地区的 20–30 条精选路线开始。每条路线均核验来源与资料，并选择代表路线进行实走测试。资料核验和团队实际走过的证据必须分别记录，不能把全部路线标为已实测。地图上的线或过去的一次实走不能证明当前通行条件。

项目同时通过真实的表结构、查询、索引、事务与迁移工作，提高负责人的 SQL 能力。学习目标必须服务于产品正确性。

## 2. 交付与费用边界

- 面向用户的产品方向为仅面向 iPhone，最低 iOS 18。已批准 React／TypeScript／Vite Web 配套，用于团队内部路线／内容工作；不增加面向消费者的 Web 功能对等版本、后端或 GL JS。其他消费者客户端平台仍不在已确认方向内。多日／高阶徒步与其他国家不属于首版承诺。
- 无需账号。行程历史本地保存。首版没有应用业务后端、账号服务或云数据库。
- 当前开发必须全免费。不得启用付费服务、付费 CI 或付费升级。试用到期或额度耗尽意味着暂停受影响服务，不代表获得付款授权。
- Mapbox Maps SDK for iOS 是**有条件选型**。依赖之前必须验证实际无卡试用、离线行为和集成。免费试用不是永久免费的生产使用资格。
- 部署后的服务费用硬上限为 NZ$50／月。Mapbox 常规计费没有自动消费硬封顶；生产费用安排解决前，它仍是发布阻塞项。不得默默放宽这一限制。
- Apple Developer Program 是后续为付费分发能力单独安排预算的费用。免费开发阶段的验收不包括 TestFlight 或 App Store 发布。
- 确定商业模式之前先验证用户需求。未经范围决策，不在首版加入支付或订阅。

## 3. 必须实现的需求

### MVP-01 — 精选路线发现与详情

浏览首批路线目录，并在选择前查看路线。展示路线几何、名称、来源，以及已有的行前信息和相关已知通行说明。展示来源更新时间或获取信息；缺失事实应标为未知，不能编造。目录必须保留稳定路线 ID、归因、核验状态和版本。

**验收：**首批 20–30 条路线都有来源核验记录；详情与所选路线一致；内置内容无网仍可读；团队实走声明有独立证据。底图和路线状态信息不能混为一谈。

### MVP-02 — GPX 路线导入

将有效 GPX 路线或轨迹导入本地存储。在已记录并验证的格式、大小和地图覆盖限制内，用户导入路线必须支持与精选路线相同的核心预览、周边地图下载、跟随、记录和偏离提醒流程。明确标为用户导入、未经团队核验。

**验收：**记录支持的 GPX 元素、多轨迹／分段处理方式及导入限制；验证坐标和时间戳；损坏或不支持的输入给出有效错误，且不破坏已有数据。保留有意义的分段边界，不默默连接缺口。导入不包含自动路线规划或重算。

### MVP-03 — 离线地图准备

出发前允许下载所选路线周边地图及必要样式资源。展示计划覆盖范围、进度、失败状态和就绪状态。只有必要资源验证通过后，才标记为可离线使用。支持重试和删除地图下载，但不得因此删除路线或行程。

**验收：**下载完成后，以飞行模式冷启动，仍能显示所选路线、可用地图文字／图标、可获取的当前位置及已记录轨迹。中断或未完成下载不得显示为已就绪。测试并记录覆盖边界、资源限制和实际包体。地图缺失时明确提示，同时保留已有路线和行程数据的访问能力。

### MVP-04 — 定位与记录状态

展示当前位置和清楚的记录状态。需要时展示精度降低、定位过期或记录中断。按需申请权限，并说明拒绝权限的影响。拒绝记录所需权限时，浏览、本地历史和文件交换仍可使用。

**验收：**拒绝权限、近似／低精度定位、定位过期与定位恢复均有可理解的状态。不得把旧位置显示为新定位，也不得用插值掩盖记录空缺。

### MVP-05 — 本地前台与后台记录

允许用户开始和结束徒步。本地记录有序轨迹点、时间戳及相关质量信息。记录必须独立于地图视图生命周期，并在平台允许的条件下支持正常锁屏和后台使用。明确控制持久化时机，并展示存储失败。

**验收：**真机证据覆盖正常锁屏、前后台切换、一日徒步时长的使用与中断恢复。保留已提交到存储的点，重新打开时识别未完成行程。记录时长、耗电和空缺。不得承诺用户强退或设备重启后仍连续记录。在将本需求标为通过之前，必须先在验证计划中确认设备覆盖、时长与量化通过阈值。

### MVP-06 — 包含锁屏的偏离提醒

在本地将合适的新鲜定位样本与所选路线比较。提供应用内提醒，并在取得授权后通过本地通知覆盖锁屏使用。过滤质量差的定位和重复提醒；记录并验证阈值。关闭通知权限必须有明确可见的影响说明。

**验收：**测试受控的沿线、偏离、低精度和重复提醒场景，包括真机锁屏通知。提醒不依赖推送服务器或在线路线计算请求。定位不确定时，不能自动给出确定的偏离判断。

### MVP-07 — 用已走轨迹辅助返回

显示已经记录的路径，让用户查看走过的路线，并据此辅助沿原路返回。

**验收：**如实呈现已保存分段与空缺，且无网仍可查看。该功能不计算新返程路线、不判定道路安全，也不提供紧急救援服务。

### MVP-08 — 本地历史与 GPX 导出

保留已完成行程，供之后查看并由用户主动导出 GPX。统计值使用已定义、已测试的计算方式，不编造缺失测量。导出必须保留所支持的坐标、时间戳与分段语义。

**验收：**应用重启后行程仍存在；导出文件可由独立 GPX 读取工具解析，并与保存数据比较。取消导出不修改行程。GPX 导出提供路线／轨迹可携带性，**不是完整应用备份**；完整备份与恢复不属于首版，后续另行评估。

### MVP-09 — 可靠的 SQL 数据与迁移

使用 SQLite＋GRDB 作为业务数据库。使用参数化 SQL、适当约束、事务写入及版本化迁移。重要 SQL 应可直接检查，便于审核和学习。业务 ID 保持稳定，并独立于 Mapbox 标识与缓存。

**验收：**提供相关写入失败与中断处理、查询／索引行为，以及携带代表数据从旧测试 schema 迁移的证据。导入或更新失败不得留下不完整用户数据。删除或替换地图缓存不得删除行程历史。PR 必须解释重要 SQL 及 schema 改动。

### MVP-10 — 版本化路线内容

初始目录以 GeoJSON 几何和 JSON 元数据随 App 打包。使用 URLSession 设计版本化静态内容更新流程；替换内容验证成功前，保留上一个可用版本。免费开发时用本地样例或本地测试端点验证更新；公开分发前确定并验证静态托管。开发验收不要求部署远程托管；托管更新属于公开发布门槛。

**验收：**安全拒绝不支持的版本、无效内容、中断下载和不兼容更新。来源 ID、归因和时间信息可追溯。定义关闭信息如何核验，以及信息过期或不可用时如何显示；没有已验证的数据源和更新机制，不得声称提供实时状态。

### MVP-11 — 隐私、权限与不可信文件

应用自己管理的行程历史默认私密、本地保存。分享和导出必须由用户主动触发。GPX／JSON 解析、日志、截图、令牌、依赖与 AI 输入遵守 [SECURITY.md](../SECURITY.md)。作出隐私声明之前，核对 Mapbox 和其他实际 SDK 的网络及遥测行为。

**验收：**测试拒绝权限的路径；个人轨迹、生产令牌和本地数据库不得出现在仓库样例或共享日志中。导入测试使用合成或获得适当授权的数据。不得将本地保存行程等同于整个应用及其 SDK 完全不发送数据。

### MVP-12 — 可用且可验证的完整流程

负责人主导代表路线上的完整真机测试，并包含一条受支持的导入 GPX 路线。重要控件与状态信息必须可读、可操作；检查主要操作的文字缩放及无障碍标签。

**验收：**验证记录覆盖路线选择／导入、离线准备、记录、后台使用、提醒、结束、历史和导出。记录设备、OS、构建／commit、路线或样例、条件、结果及遗留限制。仅模拟器运行不足以证明户外和后台可靠性。

## 4. 技术基线

| 层次 | 已确认方案 |
| --- | --- |
| 客户端 | Swift、SwiftUI、iOS 18＋；必要时接入 UIKit |
| 内部内容工具 | React＋TypeScript＋Vite，以本地开发为主的团队工具；npm lockfile、Vitest／Testing Library 与 ESLint |
| 地图 | Mapbox Maps SDK for iOS；其离线缓存与业务数据分开 |
| 定位与提醒 | Core Location 与本地通知；记录独立于地图渲染 |
| 持久化 | SQLite＋GRDB、显式参数化 SQL 与 schema 迁移 |
| 架构 | 单个模块化 App、轻量 MVVM、Swift Concurrency、清楚的数据访问边界 |
| 依赖 | Swift Package Manager；兼容性验证后锁定稳定版本 |
| 内容与交换 | GeoJSON＋JSON 目录；使用 Foundation XML 处理 GPX 导入导出 |
| 下载 | URLSession，验证后替换并保留之前可用版本 |
| 验证 | Swift Testing 验证逻辑／数据，XCTest 验证界面，结合 Xcode 诊断与真机测试 |
| 服务 | 首版没有应用业务后端、账号服务或云数据库 |

在合理范围内，让路线、记录和持久化逻辑独立于供应商的渲染类型。不为尚未确定的未来产品搭建通用抽象框架。以后变更技术时，必须说明需求、数据迁移影响、费用及验证方案。

## 5. 明确延后

- 任意起终点规划、途中改线和离线自动重算。
- 用户发布路线的社区、评论、动态、关注与社交互动。
- 完整应用备份／恢复、云备份与多设备同步。
- 实时位置分享及对应网络服务。
- Mapbox GL JS 浏览器工具。
- 多日／高阶徒步、全球路线覆盖及其他未经确认的功能扩展。

这些是后续候选，不是首版承诺。其他消费者客户端平台不在已确认方向内，也没有安排为后续工作。上述内部 React 工具仅支持团队内容工作。范围变化必须先通过 review，在中英两份 MVP 中同步更新，之后才成为必须完成的工作。

## 6. 验证与完成定义

### 开发验收

- 已实现范围满足 MVP-01 至 MVP-12，有可追溯证据，核心流程没有尚未解决的阻塞缺陷。
- 在声称测试通过**之前**，先选择代表路线、受支持设备、一日徒步记录时长、提醒阈值及性能／存储限制。记录选择和理由，不编造数字结果，也不把 SDK 文档当作应用已可用的证明。
- 验证 Mapbox 试用与离线行为、SDK／工具链兼容性、锁屏记录、定位质量处理、通知、GPX 互操作和数据库迁移。
- 每项检查记录为 **Passed（通过）**、**Failed（失败）**、附理由的 **Not run（未运行）**，或附解释的 **Not applicable（不适用）**。必须验收但未运行的测试仍是阻塞项。
- 按 [CONTRIBUTING.md](../CONTRIBUTING.md) 完成非 PR 作者的真人审核。文档完成或 AI review 本身不代表产品通过验收。

### 公开发布验收

除开发验收外，还需：

- 在保留 NZ$50／月硬上限的前提下，解决 Mapbox 生产费用安排；验证静态托管费用和内容更新运行情况。
- 按另行批准的预算完成必要 Apple 注册与分发步骤，并核对实际 App Store 隐私、权限和提交要求。
- 核验全部目录来源与归因，记录代表路线实测证据，如实说明信息新鲜度限制。
- 按 [SECURITY.md](../SECURITY.md) 配置并测试真实可用的私密安全报告渠道。
- 配置并验证 [CONTRIBUTING.md](../CONTRIBUTING.md) 中的 GitHub review 保护；仅有文件规则不能实现技术强制。
- 对照实际应用和 SDK 行为验证隐私声明。

**当前状态：**仓库已建立 iOS 和内部 React 基础工程、共享虚构元数据目录、SQL 存储及自动化测试。CI 覆盖文档、贡献元数据、Web 和可移植 Swift／数据检查；iOS 构建和 UI 验证由本地 Mac／Xcode 执行。[开发指南](guides/DEVELOPMENT.md)与[基础工程验证记录](guides/FOUNDATION-VALIDATION.md)区分实际证据与待验证事项。样例目录不是 20–30 条已核验路线，本次初始化不代表任何 MVP 需求已通过验收。离线地图、定位／记录、提醒、GPX、真实内容和发布门槛仍待完成。
