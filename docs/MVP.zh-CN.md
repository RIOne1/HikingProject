# 首个发布版本 MVP

**状态：** 已确认的规格；本次文档更新不代表新增规划、账号和发布功能已经实现或通过验收。

**决策基线：** 2026 年 11 月 13 日，[Issue #9](https://github.com/RIOne1/HikingProject/issues/9)。

**权威版本：** [英文文档](MVP.md)为主版本。本镜像必须保留相同的需求编号、范围与验收条件；含义变化时在同一 PR 中同步更新。协作遵循 [CONTRIBUTING](../CONTRIBUTING.md)，安全与私人数据处理遵循 [SECURITY](../SECURITY.md)。

## 1. 产品目标与用户

面向在新西兰进行半日或一日徒步的初级至中级用户，提供原生 iPhone App、Web 规划器及管理员控制台。核心流程为：

**Web 精细规划，或手机组合临近路线 → 保存私人计划 → 同步至 iPhone → 下载离线使用 → 跟随并记录行程 → 提供反馈 → 主动提交完成证据 → 管理员审核 → 发布供其他人选择。**

用户也可以选择已有路线或私人导入 GPX，在本地记录并导出自己的行程。报告路况不要求走完整条路线。发布批准、来源核查及过去走完的记录均不能证明当前安全或通行条件。

先验证**一个相连且方便实测的试点区域；具体地点尚未确定**。验收依据是网络场景：路口、环线、原路往返、重复经过同一条边、部分路段及不连通的选择。原先 20～30 条精选路线改为后续内容目标，不能代替可用网络，也不再是首版最低数量要求。来源／通行条件核查与实际实走分别记录。

团队规模为 2～3 人，由项目负责人主导 AI 辅助开发与测试。SQL 实践学习仍是目标，通过可审阅的查询、约束、事务和迁移支持产品正确性。

## 2. 交付与费用边界

- Mobile 面向 iPhone、iOS 18+。Web 使用 React/TypeScript/Vite，提供普通用户规划、报告及管理员功能，界面与权限分开。其他原生平台、多日／专业徒步及全球覆盖不是首版承诺。
- 游客可以浏览、本地记录及使用已下载路线。账号所属计划的同步、报告和发布申请需要登录。登录过期或后端不可用不得阻断已有离线使用。
- 使用本地 Supabase：PostgreSQL、PostGIS、Auth 和行级安全（RLS）。团队开发使用真实本地 Auth 身份、邮箱＋密码及本地捕获的测试邮件。这一简化仅适用于团队开发，不适用于外部用户账号体系。
- 当前开发阶段**必须全免费**。使用本地服务、合成测试数据和现有自托管 CI。不得启用付费服务、付费 CI 或升级；允许的免费额度／试用结束后，暂停受影响的使用。
- Mapbox iOS SDK 与 Mapbox GL JS 均为有条件选型。验证允许的免绑卡访问、实际限制、离线行为和 SDK 兼容性。地图渲染并不提供已核查步道网络，也不保证路由服务保留指定路段。图数据与路由实现仍需验证后决定。
- 部署后的服务预算仍为**每月 NZ$50 硬上限**，涵盖地图、后端、托管、邮件及相关服务总和。Mapbox [没有自动账单封顶](https://docs.mapbox.com/accounts/faq/can-i-set-up-a-cap-for-monthly-spending/)，生产费用和运行限制仍是发布阻塞项；费用提醒不等于封顶。
- Apple Developer Program 是后续单独批准预算的分发费用。免费开发不包含 TestFlight／App Store 发布。验证需求后再决定商业化；本 MVP 不包含支付和订阅。

## 3. 必须具备的需求

### MVP-01 — 路线发现与详情

浏览精选路线及管理员批准的公开路线，查看几何、来源、版本、可用规划信息和已知通行说明。显示署名、核查状态以及来源更新／获取时间。缺失事实标为未知。保留稳定路线 ID，区分来源核查、实走证据和发布批准。

**验收：** 详情与所选版本一致；已下载内容离线可读。试点内容覆盖第 1 节网络场景，并记录来源／通行核查和代表性实走证据。不要求固定 20～30 条。地图线条、批准发布的路线及当前路线状态不能视为同一种事实。

### MVP-02 — 私人 GPX 路线导入

将支持的 GPX 路线／轨迹导入本地，在经过测试的格式、大小和覆盖范围内支持预览、周边地图准备、跟随、记录及偏离提醒。标明私人、用户导入、未经核查。它们不会自动成为已核查网络路段、可发布路线或 App 实际完成的证据。

**验收：** 记录支持的元素、多轨迹／分段处理与限制，验证坐标和时间戳。无效或不支持的输入给出有效错误提示，且不损坏数据。保留有意义的间断，不虚构连接线。验证私人离线流程；能够识别受影响路段时应用已知封闭限制，不声称未知 GPX 通行条件已经核查。

### MVP-03 — 离线地图准备

出发前下载所选路线版本及周边地图／样式资源。显示覆盖范围、进度、失败和就绪状态。离线包保留路线几何、有序组成、版本及最后已知状态；地图缓存与业务数据分别管理。资源完整并通过验证后才可标为就绪。

**验收：** 飞行模式冷启动能显示保存的路线、可用地图标注／图标、可获取的当前位置及已记录轨迹。未完成下载不能显示就绪；测试重试、覆盖边界、资源限制和大小。地图移除或故障保留路线／行程。替换中断时保留此前可用包。明确离线状态是最后已知信息，不保证当前有效。

### MVP-04 — 定位与记录状态

显示当前位置与记录状态，包括精度降低、定位过期和中断。需要时解释权限；拒绝权限不影响浏览、历史记录或文件交换。

**验收：** 拒绝权限、近似／低精度定位、过期及恢复定位均有清晰可理解的状态。旧定位不能显示为新定位，不得通过插值掩盖间断。导航显示相对保存路线的位置和进度，不承诺逐转向语音导航。

### MVP-05 — 本地前台与后台记录

支持开始和结束行程，在本地保存有序轨迹点、时间戳及质量信息，与地图渲染独立。支持 iOS 允许的正常锁屏／后台行为，并暴露存储失败。

**验收：** 真机证据覆盖锁屏、前后台切换、一日徒步时长使用及中断行程恢复。重新打开后保留已提交点并识别未完成行程，记录时间、耗电和间断。不承诺强制退出或设备重启后持续记录。通过验收前，先约定设备覆盖、时长和量化阈值。

### MVP-06 — 偏离提醒，包括锁屏

在本地比较合适的近期定位与保存路线。提供 App 内提醒，以及获授权的本地锁屏通知。过滤低质量定位和重复提醒；记录并验证阈值以及拒绝通知权限的影响。

**验收：** 受控的位于路线上、偏离、低精度及重复提醒场景包含真机锁屏送达。提醒不依赖推送服务器或在线路由。定位不确定时不能得出肯定的偏离判断。本功能不包括离线自动重规划。

### MVP-07 — 显示已记录路径以辅助返回

显示用户已经记录的路径，帮助查看和沿已走路径返回。

**验收：** 已记录分段与间断准确呈现，离线仍可见。此功能不计算新返回路线、不认证安全，也不提供救援服务。

### MVP-08 — 本地历史与 GPX 导出

在本地保留已完成行程，允许用户主动导出 GPX。统计使用已定义并测试的算法，保留支持的坐标、时间戳及分段含义，不虚构测量值。

**验收：** 重启 App 后行程保留；独立 GPX 读取器可以解析导出文件，内容与保存数据一致。取消导出不改变行程。GPX 便携交换不等于完整备份；账号同步不会自动上传全部历史行程。

### MVP-09 — 可靠 SQL 数据与迁移

iPhone 使用 SQLite＋GRDB，后端使用 PostgreSQL＋PostGIS。分别使用适合各数据库的显式参数化 SQL、约束、事务和版本化迁移。稳定业务 ID 独立于地图缓存及供应商 ID。通过 Supabase SDK 和经过审阅的 SQL／RLS 访问后端；MVP 不使用 Prisma。

**验收：** 测试相关写入失败／中断、查询／索引表现，以及从有代表性旧结构升级而不丢失数据。失败的导入／更新不能留下部分用户数据。地图／目录替换不得删除行程或私人计划。通过受控迁移工具运行服务端迁移，另通过真实客户端访问路径测试用户／角色隔离。解释重要 SQL；SQLite 迁移不能代替 PostgreSQL 迁移或 RLS 测试。

### MVP-10 — 版本化网络与路线内容

使用 GeoJSON 几何和 JSON 元数据交换，包含来源 ID、署名、时间戳及通行／核查状态。已核查网络计划还保留网络版本、连通拓扑和有序选段，不能只有显示用折线。私人 GPX 使用本地路线版本及其原有分段／间断含义；不得为适配契约虚构网络 ID 或将其吸附到已核查网络。冻结保存的几何／选段版本；网络后续编辑不得悄悄改变已保存、下载或提交的路线形状。当前通行与撤回状态仍可独立更新。

**验收：** 拒绝不支持／不兼容版本、无效拓扑／内容及中断更新，同时保留可用数据。两端对已核查网络的方向、顺序、重复边和部分路段边界含义一致。下载标明确切路线版本及适用时的网络版本，计划同步保留这些标识。同时测试不属于网络的私人 GPX 和网络计划。明确状态过期或不可用。本地测试数据／端点支持免费开发；托管交付是独立发布门槛。当前合成元数据结构不等于已完成的正式契约。

### MVP-11 — 隐私、权限与不可信输入

原始行程历史默认保留在本地且私密。计划同步、导出及发布证据分别具有明确用途。仅将用户选择的、与路线相关的轨迹片段私下提交审核。文件、账号、日志、凭证、SDK 和 AI 输入遵循 [SECURITY](../SECURITY.md)。

**验收：** 未授权用户无法读取私人计划或证据。公开路线只展示批准的路线／完成信息，不展示原始私人轨迹。拒绝权限的路径可用；个人轨迹、数据库和秘密不得出现在测试数据／共享日志中。隐私声明前验证实际 SDK 网络／遥测行为；本地存储不能证明没有对外传输数据。

### MVP-12 — 可用且可测试的端到端流程

负责人主导真机和 Web 验证，覆盖两种规划界面、同步、离线徒步及反馈／审核／发布闭环。保留游客与私人 GPX 流程。检查重要操作及状态的文字缩放、标签和可操作性。

**验收：** 记录的验证运行覆盖 Web 选段、手机组合、下载、离线／后台记录和提醒、结束／历史／导出、完成证据、管理员决定及公开发现。包含拒绝／过期登录、不连通选择、同步失败和证据不足。记录设备／浏览器／OS、构建／commit、路线／测试数据、条件和限制。仅模拟器证据不能证明户外／后台可靠性。

### MVP-13 — Web 精细路线规划

在已核查试点网络内，按整条步道、路口间路段或部分路段选择，使用吸附和途经点微调。明确保留选择的部分、方向及顺序。需要连接段时，先预览几何与信息，由用户确认后纳入路线。

**验收：** 路口、环线、原路往返、重复边及部分路段场景保留用户选择。不连通选择给出有效解释并失败，不得悄悄抄近路、裁剪或替换已选部分。未知／网络外或已确认封闭路段不得作为可用连接段。保存几何与有序组成一致。不要求野外自由画线或按固定距离分块选择。

### MVP-14 — 手机简化路线组合

在出发前且在线时，选择一条路线及临近路线，预览连接部分，确认顺序／方向，保存为完整计划。与 Web 共用已核查网络和路线契约，以简化交互代替精细编辑器。

**验收：** 组合计划保留全部所选部分及确认的连接段，包括需要时重复经过。不连通或连接段封闭时拒绝；不得悄悄缩短或替换。保存结果与预览一致，可按 MVP-03 下载。行进中规划、离线组合和自动重规划延后。

### MVP-15 — 账号与权限

使用 Supabase Auth 邮箱＋密码、稳定用户 ID、所属关系及受控管理员角色。团队开发使用测试账号和本地捕获邮件，但保留真实认证／会话／RLS 行为。游客浏览、本地记录及已有离线路线不依赖登录。登录约束同步、报告和申请，不阻断用户已有本地徒步。

**验收：** 测试游客、两个不同用户和管理员访问、拒绝操作、会话过期及账号切换，不能跨用户泄露或删除本地行程。通过捕获邮件测试确认／重置流程；服务端凭证与特权密钥不得进入客户端。外部测试前验证真实邮件确认、找回账号及账号删除。后续 Resend 集成改变邮件投递，不改变身份模型。

### MVP-16 — 私人计划同步

已登录所有者可以在 Web／手机保存私人计划，在 iPhone 获取相同版本并下载。同步包含路线几何、有序路段、来源／版本及必要规划元数据，不是全部原始行程历史的云备份。离线导航使用完整本地快照。

**验收：** Web → iPhone 及手机保存／重新打开场景保持相同的所选几何与顺序。中断／重试写入不产生重复路线或部分可用版本。过期编辑给出明确冲突／重新加载选择，不得静默覆盖较新工作。退出登录、会话过期或服务故障不阻断已有离线徒步；切换账号不得暴露其他用户云端数据。

### MVP-17 — 完成证据与审核发布

实走后，所有者提供反馈，并可主动将路线相关的 App 记录轨迹片段私下提交管理员审核，绑定确切路线版本。证据须支持完整的提交路线，包括确认的连接段和重复经过；为隐私排除无关进出位置不得掩盖路线覆盖缺失。证据支持完成只允许申请，不自动发布。证据不足需要补充证据／人工审核；明确未完成不能使整条计划路线获得资格。GPS 是支持证据，不是不可伪造的证明。

**验收：** 测试支持完成、证据不足和明确未完成、GPS 间断、遗漏连接段及重复路段，验收前用试点证据校准完成阈值。仅自行声明或导入 GPX 不能满足 App 记录要求；人工审核不能免除实际完成。区分草稿／已提交／需补证／拒绝／批准并发布／撤回状态。只有授权管理员可以发布符合条件的已提交版本；几何变更需要新版本、新审核及适用于该版本的证据。旧批准／证据不得自动继承。

### MVP-18 — 路况报告与封闭处理

已登录用户在未完成或中止行程后仍可报告路况。区分未经核实的社区报告与确认的封闭／通行信息，附来源及观察／更新时间。管理员评估报告；报告不会自动成为官方封闭信息。

**验收：** 执行操作的客户端／服务端已知的确认封闭，阻止受影响的新规划、发布和新计划导航会话的开始。测试出发前已缓存的封闭及重连后才获知的封闭；离线客户端无法执行尚未收到的更新。保留地图查看及独立记录，不强制停止正在进行的徒步／导航。封闭信息过期不等于重新开放。离线包展示最后已知状态和限制；重新联网刷新可用状态，不声称实时覆盖。

### MVP-19 — 管理员控制台与公开内容治理

授权管理员可以管理用户、维护路线／基础网络、评估状态及审核发布。重要变更记录操作者、时间、理由和受影响版本。管理员不直接编辑用户私人计划，也不浏览无关原始行程；审核访问仅限已提交证据。

**验收：** 在后端测试普通用户拒绝和管理员授权操作，不能只隐藏界面按钮。路线几何变更遵循 MVP-17，状态更新保留来源。公开 UGC 使用前验证内容过滤、举报、滥用处理、屏蔽滥用用户及可联系渠道。仅有路线批准不能满足这些运营要求；参见 [Apple UGC 指引](https://developer.apple.com/app-store/review/guidelines/#user-generated-content)。

### MVP-20 — 撤回与账号删除

允许撤回路线及用户主动删除账号，包括 App 内入口。停止服务器公开展示和继续分发撤回内容，处理相关个人数据与用户生成内容。重新联网的客户端处理撤回信息；不得删除其他人的自身行程记录或强制中断正在进行的徒步。

**验收：** 测试服务端访问移除、删除范围及已保存公开内容的重连清理，同时保留其他用户的独立记录。此保留规则不豁免正在删除账号者自身的个人数据：记录其服务端数据、证据及设备内账号数据的处理方式，并区分无关的游客本地记录。退出登录／会话过期不等于删除账号请求。不能保证即时从断网设备删除。定义清理时点、进行中徒步处理、保留规则及用户说明，并在外部／公开发布前验证。不得假设匿名化作者后即可无限保留其发布内容；对照 [Apple 账号删除要求](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion)验证实际流程。

| Mobile | Swift、SwiftUI、iOS 18+；必要时 UIKit；轻量模块化 MVVM 和 Swift Concurrency |
| Web | React＋TypeScript＋Vite；普通用户规划／报告和管理员控制台；npm lockfile、Vitest/Testing Library、ESLint |
| 地图 | 有条件采用 Mapbox iOS SDK 和 Mapbox GL JS；托管地图缓存与业务数据分离 |
| 规划 | 已核查连通网络、有序选段和确认连接段；数据供应方、图处理及路由实现需经试点验证 |
| 定位与提醒 | Core Location 和本地通知，独立于地图渲染 |
| 手机数据库 | SQLite＋GRDB；显式 SQL 和版本化本地迁移 |
| 后端 | 本地 Supabase：PostgreSQL＋PostGIS＋Auth＋RLS；Supabase SDK、显式 SQL 和 SQL migrations；不使用 Prisma |
| 身份与邮件 | 邮箱＋密码、稳定 Auth 用户 ID；现在本地测试邮件，后续验证后通过 Resend 发真实邮件 |
| 数据与传输 | 版本化 GeoJSON＋JSON、路线版本和本地快照；Foundation XML 处理 GPX；适当使用 URLSession |
| 依赖 | Swift Package Manager 和 npm；稳定兼容版本及经过 review 的 lockfile |
| 验证 | Swift Testing、XCTest、Web 测试、实现时加入 SQL／RLS 集成检查，以及真机实测证据 |
| 交付 | 现有自托管 Linux CI；本地 Mac/Xcode iOS 检查；外部托管尚未决定，生产服务／邮件尚未配置 |

Mapbox 渲染不是图／路由引擎。不得假设 PostGIS 本身解决路由，或未验证有序选段语义与成本就采用付费 Directions 服务。业务逻辑尽量独立于供应商渲染类型，但不要预先构建通用框架。新依赖和重要契约需要 review；后续换栈须说明需求、迁移、费用和验证影响。

## 5. 明确延后的内容

- 多日／专业徒步、全球覆盖及其他原生平台。
- 网络外／野外自由画线规划、行进中重规划、离线路线组合、自动重规划及逐转向语音导航。
- 全应用备份／恢复、原始历史自动云备份及实时位置分享。MVP-16 私人计划同步和 MVP-17 主动提交证据是有限的已批准传输。
- 社交信息流、关注、聊天和通用社交评价；审核发布路线和路况报告属于范围内。
- 团队开发期间的真实邮件投递。外部用户使用前必须具备，不能作为上线后的可选改进。

## 6. 验证与完成定义

### 开发验收

实现 MVP-01 至 MVP-20 的开发阶段行为，有可追溯证据、核心流程无阻塞缺陷，并完成 [CONTRIBUTING](../CONTRIBUTING.md) 要求的非作者真人 review。此阶段使用本地服务和捕获邮件；下文明确标注的外部／公开发布检查在对应阶段前仍待完成，不要求现在部署，也不阻塞无关文档／增量 PR。每项检查记为 **Passed**、**Failed**、有理由的 **Not run** 或有依据的 **Not applicable**。必需而未运行的检查阻塞其对应 PR 或阶段；文档、AI review 或 foundation 构建通过不等于产品验收。

| 尚待验证 | 相关需求通过前需要的证据 |
| --- | --- |
| 试点与网络 | 选择相连且方便实测的区域；核查许可、署名、通行来源、拓扑和代表性场景覆盖 |
| 规划可行性 | 两端证明保留指定路段、部分／重复经过、连接段确认以及不连通／封闭拒绝；据此选择图／路由实现 |
| Mapbox | 验证允许的免费访问、实际地图／离线限制、SDK 兼容性及隐私行为；不得为验证可行性产生费用 |
| 记录与完成判定 | 测试前约定设备、时长、精度／提醒／完成阈值及性能／存储限制，用含 GPS 间断的实测证据校准 |
| 后端与同步 | 实现独立 SQL 迁移、所属关系／RLS、双用户／管理员反向权限测试、版本冲突、中断同步和本地历史保留 |
| CI 环境 | 随功能加入有意义的检查；后端测试需要明确验证的免费隔离环境，不得假设当前 runner 支持嵌套 Docker |
| 撤回／删除 | 定义数据范围、清理时点与进行中徒步行为；测试断网／重连客户端并保留独立行程记录 |

### 外部测试与公开发布

邀请外部用户前，验证真实邮件确认／找回、账号删除、数据权限及隐私说明；对开放的 UGC 配置审核／举报／屏蔽／联系渠道。选择并验证已授权的免费测试环境，否则保持本地／团队内测试。本地捕获邮件不足以支持外部用户。

公开发布前还需解决服务总费用 NZ$50/月封顶、Mapbox 计费风险、托管／数据库／邮件运行及数据恢复。完成单独预算的 Apple 分发步骤；验证实际 App Store 隐私、UGC 和删除要求，包括离线撤回行为。核查来源／署名／通行信息时效、代表性实走结果和端到端保密漏洞报告渠道。维持必需的 GitHub review／检查保护；文档本身不会配置这些设置。

**当前状态：** 仅已实现 iOS 与内部 React foundation、合成元数据 schema v1、目录 SQL 存储和相应测试。现有 CI 覆盖文档、贡献元数据、Web 和可移植 Swift/SQLite，本地 Mac 证据覆盖 foundation iOS 构建／UI。尚未添加规划器、GL JS 集成、后端／Auth／RLS、同步、发布或删除系统。离线地图、记录、提醒、GPX 和真实路线内容也待实现。参见[开发指南](guides/DEVELOPMENT.md)与有日期的 [foundation 验证记录](guides/FOUNDATION-VALIDATION.md)；初始化工程或本规格均不代表任何 MVP 需求已验收。
